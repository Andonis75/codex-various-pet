# 网页生成与九状态提示

这条流程默认由 Codex 操作用户选择的 ChatGPT 网页，按需使用以下身份块和提示，不要求用户逐条复制。具体控制步骤见 [browser-playbook.md](browser-playbook.md)。仅在没有浏览器工具或用户选择手动时，将相应提示和文件名交给用户。

需要账号本身可用的图像生成权限和额度；网页可能限速、失败或改变按钮布局。Python 工具不管理登录、Cookie 或人机验证，也不保证无人值守。

## 建立角色身份

先生成或选定一张清楚的角色基准图。若已有三视图，保留正面、侧面和配色作为参考。不要混用几版尚未确定的设计。每次生成动作条都应附上可用的基准图，并复用同一身份描述。

把下面方括号替换成这个角色的实际特征；这些是提示模板，不是已经执行的工具调用：

```text
我要把参考图做成 Codex 桌面 Q 版宠物。这次只生成指定动作横条，不生成整张九行动画表。

角色身份：
- 主体：[物种 / 人物类型 / 主要轮廓]
- 头身比例：[例如大头小身体，保持参考图比例]
- 识别特征：[眼睛、发型或毛色、耳朵、角等]
- 服饰与道具：[款式、颜色、左右位置；没有就写无]
- 画风：[黏土 / 毛绒 / 平涂 / 3D 玩具等，以参考图为准]
- 固定配色：[主要色与点缀色]
- 不改变：[最重要的三到五个身份特征]

所有姿势必须是同一个角色：相同的头部大小、身体比例、服饰和道具。
真正透明背景，输出带 alpha 的 PNG；不要画棋盘格、地面、文字、编号、边框或格线。
整个人物和道具都在画布内。各姿势之间留清楚的透明间隙，不粘连、互相遮挡或越出画布。
每帧有真实肢体变化，不用整体平移、统一缩放或复制同一姿势来假装动画。
```

保留角色允许的白色细节。透明要求不是“把所有白色变透明”。

## 先验证一条

建议从 `idle` 开始：提交一条请求，等生成完成，检查身份、姿势数量和下载入口，再下载原始图片。确认原文件是可解码的 RGBA，透明区域的 alpha 确实为零。先把这一条做通，再继续其他动作，可以避免整批产物都带假透明或角色漂移。

已生成的满意行保留，不必每次失败都重做所有行。新行失败时明确指出这一行的问题，附回同一基准图，只修该行。连续出现同一缺陷时先更改描述或参考；遇到额度、登录或验证阻塞就暂停生成并保留进度。

## 九种动作的附加提示

下面各段追加到同一角色身份块。帧数是最终有效输出要求；网页若生成数量不同，应核对并显式选择或重做，不能仅声称已经符合。

### idle → `source/idle-strip.png`

```text
生成一条横向 6 姿势待机动画：自然站立、轻微呼吸起伏、开始闭眼、完整眨眼、重新睁眼、回到自然站立。
动作很小且连贯，头部大小和脚底位置稳定，不移动到画布别处。首尾可自然连接。
```

### running-right → `source/running-right-strip.png`

```text
生成一条横向 8 姿势向右跑步循环。角色身体面向画面右侧，按真实跑步时间顺序展示接地、下沉、蹬地、腾空与另一脚接地，手臂和腿协调摆动。
每个姿势保持在自己的位置，不用把角色整体往右搬。头部尺度保持一致；完整保留脚和道具。
```

### running-left → `source/running-left-strip.png`

```text
生成一条横向 8 姿势向左跑步循环。身体明确面向画面左侧，接地、下沉、蹬地、腾空与另一脚接地按时间顺序连贯。
保持同一个角色，非对称服饰和道具仍在正确的身体侧；不要把时间顺序倒着排。
```

若角色对称、右跑行已经人工认可，可以用工具支持的逐帧水平镜像得到左跑并记录来源。道具、文字或非对称服装可能不适合镜像；此时独立生成并检查左跑。

### waving → `source/waving-strip.png`

```text
生成一条横向 4 姿势友好挥手动画：从自然站立抬起手、向外挥、向内挥、柔和收回。
让手与身体清楚连接、手势能看懂，另一只手和道具不突然消失；脚底稳定，首尾能衔接待机。
```

### jumping → `source/jumping-strip.png`

```text
生成一条横向 5 姿势真实跳跃：下蹲蓄力、蹬地起跳、最高点腾空、下降接近地面、屈膝落地。
各姿势使用同一相机和相同比例。腾空姿势的脚底必须真的比站立地面高，不要每帧都把脚贴在同一水平线，也不要用缩小人物代替跳跃。四周留足透明边距。
```

### failed → `source/failed-strip.png`

```text
生成一条横向 8 姿势挫败小反应：察觉失误、停顿、肩膀微垂、低头或鼓腮、小叹气、整理状态、抬头、恢复自然站立。
保留角色性格，表情可读且轻松。不要增加脱离身体的文字、泪滴、符号或特效碎片，避免用随机换姿势代替连贯动作。
```

### waiting → `source/waiting-strip.png`

```text
生成一条横向 6 姿势等待循环：耐心站立、轻微换重心、侧头看一下、短暂停留、回正、恢复自然站立。
动作幅度小但和工作状态能区分，脚底和头部大小稳定。不新增钟表、界面、文字或漂浮符号。
```

### running（工作）→ `source/running-strip.png`

```text
生成一条横向 6 姿势专注工作循环。这里 running 指正在工作，不是跑步：根据这个角色的设定表现专注思考、操作手边固定道具或小幅有节奏的手部动作，然后自然回到起点。
道具必须与参考设计相容且逐帧一致；若没有合适道具，用专注思考和手势表达，不凭空变出设备。不要与左右跑步重复。
```

### review → `source/review-strip.png`

```text
生成一条横向 6 姿势检查成果动画：认真观察、稍微前倾、换个角度确认、思考、满意地点头、回到自然站立。
动作和等待、工作可明显区分；头部大小一致，脚底稳定。不要增加文字、界面截图或漂浮勾号。
```

## 下载真实文件

有浏览器工具时：

1. 阅读当前页面状态，确认这条生成已完成；不要把占位图当结果。
2. 使用实际生成图片的下载原图入口或工具返回的原始下载能力。
3. 将真正的下载文件存为对应 `source/<state>-strip.png`，核对文件存在、大小大于零、真实编码与透明通道。
4. 若工具下载到临时位置，只复制刚刚核验的那份文件；保留来源和状态对应关系。

无浏览器工具时：把当前状态的提示词、预期文件名和工作目录告诉用户，由用户在网页生成并下载。不要编造 Playwright、User-Agent、生成命令或文件链接来声称已经完成。

某些下载是 WebP 或 JPEG，即使文件名写了 `.png` 也不是 PNG。先解码核实格式。若原文件确有透明通道，可通过明确的格式转换保存 PNG；若原来已是扁平白底或棋盘，改扩展名和转 PNG 都不会恢复透明。

## 接回本地流程

文件齐全后运行 `inspect`，处理报告中真实的问题，再 `build` 和 `preview`。别跳过人工观看：姿势计数通过不说明跑步合理，输出有透明通道也不说明头发边缘干净。

代理实际播放并认可当前构建后才 `approve`；用户已要求安装时，代理继续执行安装，不每条等“继续”。格式和审查项见 [format.md](format.md)，具体错误见 [troubleshooting.md](troubleshooting.md)。
