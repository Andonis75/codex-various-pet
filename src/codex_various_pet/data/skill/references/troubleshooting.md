# 排错与恢复

先保留失败命令、原始错误、现有源图和质量报告。重新生成一行通常比推倒整个工作目录更容易核对。以下“成功”都应由实际工具输出或观察支持。

## 终端找不到命令

确认安装和运行使用同一个 Python 环境：

```bash
python -m pip show codex-various-pet
python -m codex_various_pet --help
```

模块入口可用时，把后面的 CLI 子命令接到 `python -m codex_various_pet` 后。技能安装包使用其自身 `scripts/run.py`，不要求全局可执行文件位于 PATH。

## 网页没有可用的图像生成 / 浏览器工具

Python 包不提供 ChatGPT 账号、订阅或浏览器会话。确认当前账号与网页能正常生成图片。登录、人机验证、付费或额度确认由用户操作。

没有浏览器控制工具时，运行 `prompts` 并手动复制到网页，下载原图到 `source/`，再继续本地检查。不要让代理反复尝试不存在的工具，也不要把手动分支说成自动执行。

额度耗尽、网页错误或长时间卡住时，保存已完成行。说明失败发生在哪一条，等账号或网页恢复后再续做；没有必要删除满意的行或循环发送整套请求。

## 文件是截图、JPEG 或假 PNG

使用真实生成图片的“下载”入口。截图丢失透明度，也可能混入网页背景。文件扩展名不等于实际编码：JPEG 改成 `.png` 仍是 JPEG。

若有真正透明的 WebP，可通过解码转换为 RGBA PNG并保留原图。若白底或棋盘已画入图中，转换格式只会保存这些背景；应重做该行或另行采用经检查的抠图方案。

不要按颜色删除所有白像素。白色衣服、眼睛高光、角和配饰会一起受损。看到灰白棋盘也不能据此认定透明，必须核对 alpha。

## 姿势数量不对、角色粘连、缺帧

先看检查图和源图：

- 相邻角色的头发或衣服接触时，检测可能合并成一个姿势。重做时要求更大透明间隙。
- 一根漂浮的装饰或碎片可能被识别成额外组。保留报告，确认它属于哪一帧；不要悄悄删除可见细节。
- 生成条缺少完整姿势时，优先重做该行。hold 复用不能补出不存在的动作。
- 多出的完整姿势可以通过明确源帧选择处理；报告应保留选择和重复关系。
- 源图已裁头、裁脚时，拼图不应伪造缺失部分，重新生成完整源图。

按 CLI 报告处理当前工作目录的配置；不知道某字段是否支持时先查看帮助和实际配置，不猜参数。

## 动作看起来像平移，或跳跃不离地

检查源条是否本来只有同一姿势的整体移动。真实跑步应有腿、手臂和重心变化；平移整张图不能代替步态。

跳跃需要源条中的脚底实际升高。若源图有升降但预览没有，检查注册和缩放记录，避免把每帧脚底强行对齐。若源图根本没有腾空，重新生成跳跃行。

横躺、下蹲和高举手动作的最大高度与站立不同。不要逐帧拉伸成一样高；通过整行尺度和参考头宽保持角色一致，再人工对比各行。

## 预览很慢，或动作演几次就站住

v1 待机使用较慢的原生节奏；其他状态通常演三轮后回待机。这是预览区分的原生行为，不必因此重做图。

使用逐帧按钮确认每帧，或切换为单状态循环。九动作顺序播放会各播一轮后停止，适合检查状态间尺度变化。浏览器后台节流、减少动态效果或打开太多页面也会影响观感。

`preview` 默认写 HTML，不等于已经打开；`--open` 会尝试打开。即使 HTML 成功生成，也应真正打开看过再记录人工认可。

## 构建或安装报哈希/认可不匹配

确认你正在安装的是刚刚审查的那个工作目录。重新构建可能改变雪碧图或质量记录；先对新构建重新预览，认可后再运行 `approve`。

`approve` 非交互，不会替你看动画。不要通过篡改哈希、质量报告或认可记录让安装表面通过。先解决真实不匹配。

## 同名目录已存在

安装默认保留已有宠物。使用另一个 slug，例如：

```bash
various-pet install ./my-pet --slug my-pet-v2
```

若想替换旧宠物，应先明确旧目录属于哪个角色、需要保留什么，再另行操作。不要顺手删除整个宠物目录或其他配置。

## 安装后桌面没有显示

1. 核对安装命令实际输出的 Codex 用户目录与所用桌面环境。设置了 `CODEX_HOME` 时可能不同于默认位置。
2. 打开该宠物目录，确认 `pet.json` 和图像存在，路径是相对的，格式/尺寸与 v1 一致。
3. `pet.json` 使用 UTF-8 无 BOM；图像扩展名与真实编码一致。旧 Windows PowerShell 的某些 UTF-8 写入方式会产生 BOM，建议由 CLI 生成。
4. 重新打开 Codex 的宠物选择界面并选择角色；若仍未加载，重启桌面应用后复核。
5. 记录具体桌面版本。仓库验证基线是 `26.1013`，后续更新应以实际结果为准。

文件已安装和界面已选中应分别报告。无法观察界面时，说清已验证到哪一步，不冒充已激活。
