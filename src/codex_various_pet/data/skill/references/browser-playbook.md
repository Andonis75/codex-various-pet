# 浏览器执行流程

目标：用户给参考图和需求后，Codex 主动操作其已登录的 ChatGPT 网页，完成生成、原图下载、缺陷重试和预览审查。CLI 是代理的内部处理工具，不是要求用户逐条执行的教程。

## 1. 确认可用控制能力

从本次实际工具目录发现浏览器工具，读取其文档。优先使用用户指定的已登录页面和浏览器，不擅自换到未登录环境。

有些环境提供持久 JavaScript 的 CUA 浏览器控制，例如 `cua.getTab`、页面快照和点击/输入；有些提供浏览器会话和文档化的 Playwright 接口。**只用当前工具公开的接口、签名和状态标识。** 不把教程中的方法当成可调用工具，也不将 shell 运行的脚本描述成实际浏览器动作。

如果 CUA 文档要求首次调用只选一个 tab/app，就按它初始化，读完返回文档后再继续。定位用户标签时使用实际观察到的 URL、tab ID 和浏览器 ID；不使用固定账号、旧对话链接或猜测 ID。状态标识过期后重新读取，不盲点旧坐标。

没有实际浏览器工具时，明确转手动回退并提供当前行提示词与目的文件名。安装本包不会提供浏览器控制。

## 2. 准备与上传参考

1. 从仓库起步时先读 README/AGENTS，内部调用 `tools/bootstrap.py`。按 JSON 返回的 Python 路径执行模块；安装技能起步则使用其 `scripts/run.py`。这一步由代理完成。
2. 获得附件真实本地路径或当前工具支持的文件引用。确认可解码，不编造路径。
3. 运行 `init`，记录身份和需求到 `identity.md`，生成 `prompts.md`。已有项目检查后续做，不重建覆盖。
4. 读取用户网页当前状态，确认已登录、输入框可用。需登录或人机验证时交用户处理，保留待继续的状态。
5. 用实际可见的上传控件和工具文档支持的上传能力附上参考图。等待上传完成；不能只把本机路径粘贴给网页当作已上传。
6. 提交身份块和制作目标。保留用户确定的设计，只在关键身份不明时提问，普通动作规划由代理决定。

每条请求沿用同一身份，可在同一网页对话继续。上下文若丢失参考，重新附上基准图，不依赖模型记住很久以前的图片细节。

## 3. 先做 idle，验证真实下载

1. 使用 [web-generation.md](web-generation.md) 的身份块和 idle 提示，提交一次请求。
2. 观察真实进度，等生成完成。占位框、转圈和缩略图不等于原图已下载。等待和轮询遵守当前工具文档，并向用户简短汇报实际进展。
3. 检查身份和姿势，使用生成图片实际出现的原图下载控件或公开下载能力。控件需悬停/展开时先读页面与工具支持，不猜后端接口。
4. 从实际下载结果取文件，复制为工作目录的 `source/idle-strip.png`。核对真实编码、尺寸、透明通道，用图像查看工具看真实像素。
5. 运行 `inspect` 并看检测图：人物完整、间隙清楚、姿势数合理。透明图应有真实 alpha；棋盘留在 RGB 像素中仍是假透明。

不得自造 `file_id`、下载地址、Playwright 调用或 User-Agent 脚本后宣称生成成功。下载为 WebP 时保留原图并解码；确有透明通道时才做格式转换。不要把 JPEG/白底图改名为 PNG 绕过检查。

## 4. 逐状态生成并修缺陷

idle 整条链路通过后继续右跑、左跑、挥手、跳跃、挫败、等候、工作、检查。一次完成一条；生成等待时可以检查已有行，不打断正在运行的网页任务。

- 每条生成后下载原文件，保留状态对应关系，快速核对完整性和身份。
- 角色左右对称且右跑已实际看过、方向与步态合格时，可在 `source/assembly.json` 显式认可右跑并逐帧水平镜像。非对称服饰、道具和纹样应独立生成左跑；镜像不是倒放时间。
- 漏帧、粘连、裁头、假透明、身份漂移或跳跃不离地时，引用当前缺陷发出针对该行的修正请求，附回基准图。下载新版本再检查，保留旧版比较。
- 重试应有依据和进展。额度/账号阻塞、下载能力缺失，或同一缺陷反复且无有效修正时停止消耗，保留接受行并说明阻塞。
- 用户已授权制作时，不每条问“继续吗”。文件命名、普通检查、重试和组装由代理继续完成。

报告保留源帧选择、hold 和镜像。不能静默删可见残片伪造通过，也不能把复制计为新增独立生成帧。

## 5. 组装后由代理内部审查

1. 内部运行 `inspect`，修复报告问题，再 `build`。
2. 自行查看真实接触表、GIF 和按时间顺序的帧图。审查所有九种动作的完整周期和帧时长；如果工具只显示 GIF 首帧，解码查看完整帧序列，不能说已经播放过。
3. 需要交互检查时才运行 `preview`。通过当前支持的浏览器入口打开真实 HTML，用播放、逐帧、1×/2×、背景和格线检查；仅支持网页时可使用只绑定回环地址、只服务本次目录的临时服务。不要求用户再操作独立预览网页。
4. 检查脸/头宽/服装一致，脚底不飘，跑步有肢体变化，跳跃有蓄力、升起、下降和落地，边缘没有相邻角色或背景残留。
5. 不合格回到对应源行，重新组装再看；不只根据 HTML 已生成或几何标记就执行认可。

临时预览用完，关闭自己创建的预览标签并停止自己启动的服务，保留用户原 ChatGPT 页面和项目产物。若确实没有任何实际图像/动画查看能力，说明视觉审查尚缺；不能只读质量 JSON 就伪造“已经看过”。

## 6. 已授权则自行安装

已实际看完并接受当前构建，且用户要求安装时，由代理内部执行 `approve` 与 `install`。认可记录对应代理这次实际视觉审查，不是程序自动判断艺术质量。

保留已有安装目录。新角色/修订可选未占用 slug，报告最终名称与位置。验证 manifest、图片与哈希。若有当前受支持的桌面控制能力，完成并观察宠物选择；没有则给用户剩余的选择动作。

最终分清生成下载、构建、视觉审查、文件安装、应用显示各阶段。用户通常只处理必要的登录/验证并查看结果，不承担代理能做的每条命令。
