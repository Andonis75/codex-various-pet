# Codex 桌宠 v1 格式与验收

本仓库当前处理 v1。已按 Codex 桌面 `26.1013` 核验。官方功能介绍：[Pets](https://learn.chatgpt.com/docs/pets)。未来桌面版本若改变行为，应以实际加载结果复核，而不是直接宣称长期兼容。

## 雪碧图

- 整图：**1536×1872 像素**。
- 网格：8 列 × 9 行。
- 每格：**192×208 像素**。
- 本工具输出带真实透明通道的 PNG。
- 帧从左往右排列；行动作由上往下固定。
- 一行尾部未使用的格保持透明。总有效输出格数为 **57**。

| 行索引（0 起） | 名称 | 有效帧 | 各帧原生时长（ms） |
|---:|---|---:|---|
| 0 | `idle` | 6 | 1680, 660, 660, 840, 840, 1920 |
| 1 | `running-right` | 8 | 120 × 7, 220 |
| 2 | `running-left` | 8 | 120 × 7, 220 |
| 3 | `waving` | 4 | 140 × 3, 280 |
| 4 | `jumping` | 5 | 140 × 4, 280 |
| 5 | `failed` | 8 | 140 × 7, 240 |
| 6 | `waiting` | 6 | 150 × 5, 260 |
| 7 | `running` | 6 | 120 × 5, 220 |
| 8 | `review` | 6 | 150 × 5, 280 |

`running` 是“专注工作”状态，与左右跑步不同。待机本身比较慢，不要因眨眼间隔长就判断动画停止。

原生普通播放中，待机持续循环；其他动作通常重复三轮后回待机。预览的“九动作依次一轮”是检视用顺序播放，不等同于桌面触发状态的调度。减少动态效果设置也可能影响实际表现。

## 从生成条到固定网格

生成器不必一次准确输出最终雪碧图。推荐先生成各动作的横条原图，保留完整姿势、透明间隙和安全边缘，再由工具提取与拼接。

整行应采用一致缩放，不要把每一帧分别缩放到相同最大高度；否则蹲伏会长高、跳跃会丢失位移。非跳跃行保持脚底注册稳定，跳跃行保留源图实际的升降。不同动作之间需人工比对头部大小和形体比例。

源图多帧不代表全都该用。允许在明确配置和报告中选择有效源帧。一个源帧被复用时，应记录为 hold；水平镜像也应记录派生关系，不能说成又生成了一套独立姿势。源图缺少真正步态或跳跃时，复制帧不能修复动作语义。

显式处理配置位于工作目录的 `source/assembly.json`。修改前先查看 `inspect` 报告和已有配置，保留无关字段。比如待机源图有 8 个完整姿势，人工选定其中 6 个时，可设置零起索引：

```json
{
  "states": {
    "idle": {"indices": [0, 1, 2, 3, 4, 6]}
  }
}
```

只有当右跑已实际看过且适合镜像时，才设置 `running-right.approved` 为 `true`。`running-left.mirror` 为 `"running-right"` 且没有独立左跑源图时，工具可逐帧镜像：

```json
{
  "states": {
    "running-right": {"approved": true},
    "running-left": {"mirror": "running-right"}
  }
}
```

这里的右跑 `approved` 只允许该派生操作，不代替最终 `approve` 对整个构建的人工认可。初始配置不会自动认可右跑。

## 文件与 manifest

安装到 CLI 实际解析的 Codex 用户目录中：

```text
<Codex 用户目录>/pets/<slug>/
  pet.json
  spritesheet.png
```

通常用户目录是 `~/.codex`，设置了 `CODEX_HOME` 时以实际配置和 CLI 输出为准。

v1 manifest 示例：

```json
{
  "displayName": "猫猫",
  "description": "戴围巾的小猫 Codex 桌面宠物",
  "spriteVersionNumber": 1,
  "spritesheetPath": "spritesheet.png"
}
```

使用 UTF-8 无 BOM，图片路径相对于这个宠物目录，扩展名应与真实文件一致。仅改扩展名不会转换图片编码。一个新宠物用独立 slug；CLI 不覆盖已存在的安装目录。

本工具不依赖私有会话、账号信息或应用内部私有接口。复制本地文件后仍需到桌面选择宠物并确认显示。

## 几何检查与视觉审查

自动检查负责实际可以测量的内容：真实图像格式、alpha、姿势分组、源图边缘风险、输出尺寸与格子、文件哈希及当前构建对应关系。检测算法也会遇到粘连和道具造成的分组歧义，报告应辅助观察。

人或具备实际视觉工具的代理至少检查：

1. **身份**：脸型、发型或毛色、服装、道具位置、画风与比例一致。
2. **透明边缘**：无画进去的棋盘、白底、相邻角色残片、漂浮黑点、裁头或裁脚。
3. **注册**：站姿脚底稳定、头部大小稳定；动作内部不随机缩放。
4. **步态**：跑步有接地、蹬地、离地和摆臂等肢体变化，方向正确。
5. **跳跃**：有蓄力、起跳、离地、落地；保留实际垂直位移。
6. **语义与循环**：挥手、挫败、等待、工作、检查彼此能区分，回到待机不突变。

`approve` 把运行者已完成的视觉审查关联到当前构建。它是非交互记录，本身不会分析图片。代理已经实际播放、查看并认可动作，且用户授权安装时，可以由代理执行，无需让用户再逐步敲命令。改动后先重新检查和观看，再认可新构建；不要篡改记录以绕过安装要求。
